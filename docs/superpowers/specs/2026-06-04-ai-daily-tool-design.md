# AI 早报工具设计文档

日期：2026-06-04
状态：对话内已确认，等待后续按计划实现

## 1. 目标

构建一个个人使用的 Web AI 资讯阅读工具，持续抓取用户维护的 X 白名单账号最新原创内容，并以实时流的方式展示。

第一版优先保证：

- 抓取稳定
- 阅读清晰
- 网页可配置
- 适合部署在云服务器

第一版不优先处理：

- AI 内容筛选
- 多用户支持
- 消息推送
- 复杂的多服务基础设施

## 2. 产品范围

### 第一版包含

- 个人使用
- 网页作为主要使用入口
- 指定 X 账号白名单作为唯一内容源
- 只抓原创帖
- 抓到的内容全部展示
- 保留英文原文并由系统生成中文翻译
- 实时流页面
- 今日汇总页面
- 账号、分组、抓取、代理、翻译设置的后台页面
- 基于代理池的抓取基础设施
- 可插拔的 X 数据源适配器设计

### 第一版不包含

- AI 筛选或排序
- 重要性评分
- 标签体系
- 引用帖、转推、回复
- 推送能力
- 面向公众的产品化能力
- 多租户权限系统
- 依赖 X 自带翻译结果

## 3. 已确认需求

用户已确认以下产品方向：

- 面向对象：个人工具
- 主要使用方式：网页查看
- 信息来源：指定 X 账号白名单
- 展示粒度：全量展示，不筛选
- X 接入方式：数据源层必须可替换
- 代理池含义：网络代理 IP 池，用于对抗反爬
- 时间窗口：首页看近实时，同时保留今日汇总页
- 首页排序：按时间倒序
- 展示语言：英文原文 + 中文翻译
- 配置方式：优先网页后台，而不是改代码
- 内容类型：只抓原创帖
- 非 AI 强相关内容：来自白名单账号也照常保留
- 账号维护方式：按分组管理
- 部署方式：优先按云服务器设计，同时保留本地运行可能

## 4. 架构设计

第一版采用单个 Web 应用配合异步后台任务和单数据库的结构。

这样部署简单，同时内部边界仍然清晰。

### 4.1 核心模块

#### 调度器

负责：

- 按账号分组和配置频率触发抓取任务
- 控制并发
- 重试失败任务
- 记录运行结果

#### X 抓取器

负责：

- 为指定白名单账号拉取新的原创帖
- 将不同数据源返回的结果标准化为统一内部格式

内部再拆成：

- 数据源适配器
- 代理 session 管理器

#### 数据源适配器

提供稳定的抓取接口。

应用层不能直接依赖某一种具体 X 接入方式。后续可替换为：

- 官方 API
- 第三方 API
- 浏览器自动化方案

#### 代理 Session 管理器

负责：

- 使用用户提供的代理池
- 管理轮换 session 或黏性 session
- 跟踪超时与失败
- 在需要时切换代理或 session

代理池属于抓取基础设施，不是用户界面的核心产品概念。

#### 翻译流水线

负责：

- 将抓取到的非中文内容翻译为中文
- 以异步方式更新翻译状态

第一版只做翻译，不做内容筛选、排序或标签。

#### 存储层

负责持久化：

- 白名单账号
- 账号分组
- 原始抓取结果
- 翻译结果
- 抓取运行记录
- 系统设置

#### Web 界面

拆成：

- 面向阅读的前台页面
- 面向配置的后台页面
- 面向运维的系统状态页面

## 5. 数据流

一次抓取任务的完整路径如下：

1. 调度器按账号组触发抓取任务。
2. X 抓取器通过数据源适配器和代理 session 管理器拉取新原创帖。
3. 返回结果被标准化为统一内部帖子格式。
4. 按账号和帖子 ID 做去重。
5. 原始帖子立即入库。
6. 需要翻译的内容进入翻译任务队列。
7. 首页按发布时间倒序展示全部内容。
8. 今日汇总页展示当天全部卡片。

### 核心原则

- 第一版不做内容筛选
- 第一版不做重要性评分
- 原始抓取数据和翻译结果分开存储
- 翻译失败不能阻塞帖子入库与展示

## 6. 数据模型

具体字段名后续可以在实现时微调，但这些实体必须存在。

### 6.1 `source_accounts`

字段：

- id
- x_handle
- display_name
- group_id
- enabled
- created_at
- updated_at

### 6.2 `account_groups`

字段：

- id
- name
- description
- default_fetch_interval
- created_at
- updated_at

### 6.3 `raw_posts`

字段：

- id
- source_account_id
- external_post_id
- original_text
- original_language
- posted_at
- fetched_at
- source_type
- raw_payload

唯一约束：

### 6.4 `post_translations`

字段：

- id
- raw_post_id
- translated_text_zh
- status
- error_message
- model_name
- model_version

- status
- fetched_count

- 翻译模型设置
- 翻译提示词设置

## 7. 前台页面设计

前台应保持紧凑、偏阅读器风格。

### 7.1 实时流

用途：

- 展示全部已抓取内容，最新内容优先

每张卡片至少包含：

- 账号显示名
- 账号 handle
- 所属分组
- 发布时间
- 英文原文
- 中文翻译
- 原帖链接

页面顶部提供基础筛选：

- 按分组筛选
- 按账号筛选
- 按时间窗口筛选，例如最近 3 小时、24 小时、今天

### 7.2 今日汇总

用途：

- 展示当天全部抓取到的卡片

这不是 AI 自动生成的摘要，而是按当天范围聚合出来的浏览页。

### 7.3 系统状态

用途：

- 让用户快速判断系统是否健康

至少显示：

- 最近抓取任务记录
- 最近一次成功抓取时间
- 成功/失败数量
- 翻译队列状态
- 最近错误信息

## 8. 后台设计

后台应以“可配置”为核心，而不是依赖改代码。

### 8.1 账号管理

能力：

- 新增账号
- 删除账号
- 启用/停用账号
- 将账号分配到分组

### 8.2 分组管理

能力：

- 创建分组
- 编辑分组
- 删除分组
- 设置分组默认抓取频率

### 8.3 抓取与代理设置

能力：

- 配置全局抓取频率
- 配置并发上限
- 配置重试次数
- 配置超时阈值
- 配置数据源适配器
- 配置代理供应商参数
- 选择轮换模式或黏性模式

### 8.4 翻译设置

能力：

- 配置翻译模型
- 配置翻译提示词
- 决定是否自动处理历史积压内容

## 9. 代理相关要求

代理服务商提供的示例代码只说明“如何连上代理”，不等于抓取模块已经完整。

抓取层还必须补齐：

- 代理提供器抽象
- session 管理
- 超时处理
- 重试策略
- 健康检查
- 失败分类

应用层应该暴露类似 `ProxyProvider` 的抽象，抓取器只依赖这个抽象，不直接依赖某一家代理服务商的参数形式。

## 10. 可靠性与异常处理

第一版必须处理下面几类问题。

### 10.1 抓取失败

示例：

- 代理连接失败
- 代理认证失败
- 超时
- 目标站拒绝访问

要求：

- 记录错误原因
- 在适合的情况下重试
- 在适合的情况下切换代理或 session
- 单个任务失败不能阻塞其他抓取任务

### 10.2 重复抓取

要求：

- 按账号 + 帖子 ID 做幂等去重
- 重跑任务不应重复生成帖子记录

### 10.3 翻译失败

要求：

- 原文照常展示
- 翻译状态标记为处理中、失败或待重试
- 支持不重新抓取原帖的前提下重试翻译

### 10.4 数据源切换

要求：

- 前台、存储层、调度层不关心当前使用哪个抓取适配器

### 10.5 后台配置错误

要求：

- 对抓取频率、并发、超时、代理格式等关键参数做校验
- 拒绝明显错误或危险值

## 11. 测试范围

### 11.1 单元测试

- 代理配置解析
- 抓取结果标准化
- 去重逻辑
- 翻译状态流转

### 11.2 集成测试

- 调度器到抓取到入库的完整链路
- 翻译任务执行
- 代理失败时的重试逻辑

### 11.3 界面验证

- 实时流按时间倒序
- 分组/账号/时间筛选正确
- 今日汇总内容正确
- 状态页能看见失败记录

### 11.4 运行验证

- 云服务器部署后进程常驻
- 调度器重启后可恢复
- 最近抓取状态对用户可见
- 日志足以辅助定位问题

## 12. 成功标准

第一版成功的标准是：

- 用户可以在网页后台管理 X 账号和分组
- 系统可以定时抓取这些账号的新原创帖
- 首页能稳定展示英文原文和中文翻译
- 今日汇总页能正确展示当天内容
- 系统状态页能让用户快速定位大致问题

## 13. 后续增强方向

下列能力适合作为下一阶段增强，但明确不放入第一版：

- AI 内容筛选
- 重要性评分
- 标签体系
- 引用帖/回复/转推抓取
- 推送分发
- 更丰富的数据分析
- 并行启用多个抓取源

## 14. 约束与说明

- 不能把 X 内置翻译视为稳定可抓取字段。
- 中文翻译由系统自己完成。
- 当前实现计划已经切换到 Next.js + Tailwind CSS + TypeScript 技术栈，后续开发以实现计划为准。
